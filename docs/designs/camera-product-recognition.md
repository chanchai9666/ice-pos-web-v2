# Camera-based Product Recognition (ระบบสแกนหาสินค้าจากภาพถ่ายผ่านกล้อง)

- **Author:** chanchai9666
- **Status:** Draft
- **Date:** 2026-11-04

## Overview

ระบบค้นหาและระบุสินค้าด้วยภาพถ่ายจากกล้อง (Webcam บน PC หรือกล้องอุปกรณ์เคลื่อนที่/แท็บเล็ต) ทำงานแบบ Offline-first บนเบราว์เซอร์ของแคชเชียร์ เพื่อช่วยระบุและเพิ่มสินค้าลงตะกร้าขายสำหรับร้านค้าปลีกขนาดเล็ก โดยใช้โมเดล Visual AI ในการสกัดเวกเตอร์รูปภาพและค้นหาความคล้ายคลึง (Cosine Similarity) เทียบกับแคตตาล็อกสินค้าที่เก็บแคชใน IndexedDB

## The Problem

ในร้านค้าปลีกขนาดเล็ก สินค้าหลายประเภทไม่มีรหัสแท่งบาร์โค้ดพิมพ์ติดมากับตัวสินค้า (เช่น ถุงน้ำแข็งแบ่งบรรจุ, สินค้าเกษตร, ขนมแบ่งขาย) หรือในบางกรณีป้ายบาร์โค้ดเปียกชื้น ฉีกขาด หรือพิมพ์เลือนราง ทำให้แคชเชียร์ต้องเสียเวลาค้นหาชื่อสินค้าด้วยการพิมพ์ค้นหาทีละรายการ ซึ่งทำให้กระบวนการคิดเงินล่าช้า เกิดแถวคอยหน้าร้าน และมีโอกาสเลือกรายการสินค้าหรือราคาผิดพลาด

การนำระบบรู้จำสินค้าด้วยภาพ (Visual Product Recognition) มาช่วยค้นหา จะช่วยลดเวลาในการป้อนข้อมูล แต่ความท้าทายหลักคือ:

1. ระบบหน้าร้านต้องทำงานได้ต่อเนื่องแม้ระบบอินเทอร์เน็ตขัดข้อง (Offline-first)
2. อุปกรณ์หน้าร้านมีหลากหลาย (ทั้ง PC และแท็บเล็ต/สมาร์ตโฟน) ซึ่งมีข้อจำกัดด้านหน่วยความจำและพลังประมวลผล
3. สินค้าปลีกมักมีบรรจุภัณฑ์หรือสีที่ใกล้เคียงกัน การระบุสินค้าอัตโนมัติ 100% (Auto Add to Cart) เสี่ยงต่อการคิดเงินผิดพลาด

## Goals

- **Offline-First Visual Search**: แคชเชียร์สามารถเปิดกล้องส่องสินค้าเพื่อค้นหารายการสินค้าในแคตตาล็อกได้แบบ Offline 100% โดยอาศัยข้อมูล Vector Embeddings ที่ซิงค์มาเก็บไว้ใน IndexedDB
- **Prevent False Positives with Semi-Automatic UX**: ลดความผิดพลาดในการคิดเงินด้วยการให้แคชเชียร์ตรวจสอบและเลือกยืนยันรายการ (Single-tap confirmation สำหรับคะแนนความมั่นใจสูง และแสดงตัวเลือก Top 3-5 เมื่อความมั่นใจก้ำกึ่ง)
- **Responsive Multi-Device Support**: รองรับทั้ง PC ผ่านกล้องเว็บแคม และอุปกรณ์เคลื่อนที่/แท็บเล็ตผ่านกล้องหลัง/กล้องหน้า
- **Non-Blocking UI Execution**: แยกการคำนวณเวกเตอร์และเฟรมภาพไปรันบน Web Worker เพื่อรักษาความลื่นไหลของหน้าจอขายหน้าร้าน (Maintain 60 FPS บน Main Thread)

## Non-Goals

- **No Multi-Object Bounding Box Detection**: ไม่รองรับการตรวจจับวัตถุหลายชิ้นพร้อมกันในเฟรมเดียว (เน้นส่องสินค้าทีละชิ้น)
- **No On-Device Model Training**: ไม่รองรับการฝึกฝนโมเดลใหม่บนเครื่องลูกข่าย (Client)
- **No Real-time Cloud Streaming Fallback**: ไม่ส่งสตรีมวิดีโอไปประมวลผลบนเซิร์ฟเวอร์แบบ Real-time เพื่อลดภาระเซิร์ฟเวอร์และค่าใช้จ่ายคลาวด์
- **No Enterprise Vector DB Scalability**: ไม่รองรับฐานข้อมูลสินค้าระดับแสนรายการ (ระบบนี้ออกแบบสำหรับร้านค้าขนาดเล็กที่มีสินค้าไม่เกิน 1,000 รายการ)

- **Question 2**: ควรมีการเก็บสถิติความถี่ในการสแกนสำเร็จ/ไม่สำเร็จ (Telemetry / Accuracy logs) ไว้ใน IndexedDB เพื่อซิงค์ส่งกลับมาวิเคราะห์ปรับปรุงโมเดลในอนาคตหรือไม่?

## Critical User Journeys (CUJs)

### CUJ 1: แคชเชียร์สแกนสินค้าที่ไม่มีบาร์โค้ดผ่านกล้องหน้าร้าน

- **Given**: แคชเชียร์เปิดหน้าจอขาย POS บน PC หรือแท็บเล็ต โดยเบราว์เซอร์ได้ซิงค์ข้อมูลสินค้าและแคชโมเดล Vision AI ไว้เรียบร้อยแล้ว
- **When**: แคชเชียร์กดปุ่ม "สแกนด้วยกล้อง (Camera Scanner)" แล้วส่องกล้องไปที่ถุงน้ำแข็งหรือสินค้าที่ไม่มีบาร์โค้ด
- **Then**:
  1. หน้าจอแสดงภาพพรีวิวจากกล้องพร้อมกรอบช่วยเล็ง
  2. ระบบวิเคราะห์ภาพผ่าน Web Worker และพบสินค้าที่มีความคล้ายคลึงสูงสุด (Confidence >= 0.85)
  3. ระบบแสดงบัตรสินค้าที่ตรงกันพร้อมราคาและปุ่ม "เพิ่มลงตะกร้า" ให้แคชเชียร์แตะยืนยัน 1 ครั้ง
  4. สินค้าถูกเพิ่มลงในรายการขายทันที พร้อมเสียงตอบรับ (Audio Beep)

### CUJ 2: ระบบพบสินค้าที่มีลักษณะใกล้เคียงกันหลายรายการ (Ambiguous Match)

- **Given**: แคชเชียร์เปิดกล้องส่องสินค้าที่มีบรรจุภัณฑ์คล้ายกัน (เช่น ขวดน้ำดื่มต่างยี่ห้อ หรือน้ำอัดลมต่างรสชาติ)
- **When**: กล้องจับภาพสินค้าและคำนวณค่า Cosine Similarity พบว่าคะแนนอยู่ในช่วง 0.70 - 0.84 หรือคะแนนของอันดับ 1 และอันดับ 2 ใกล้เคียงกันมาก (< 0.05 ต่างกัน)
- **Then**:
  1. ระบบไม่เพิ่มสินค้าลงตะกร้าโดยอัตโนมัติ
  2. หน้าจอแสดงรายการแนะนำ (Top 3 Matches) พร้อมรูปขนาดย่อ ชื่อสินค้า และราคา
  3. แคชเชียร์แตะเลือกรายการที่ถูกต้องเพื่อเพิ่มลงตะกร้า

### CUJ 3: ผู้ดูแลระบบเพิ่มรูปถ่ายสินค้าและสร้างเวกเตอร์จากหน้าจัดการสินค้า (Admin)

- **Given**: ผู้ดูแลระบบเปิดหน้าแก้ไข/เพิ่มสินค้า (Product Catalog Admin)
- **When**: ผู้ดูแลระบบอัปโหลดรูปภาพสินค้าใหม่ หรือถ่ายภาพสินค้าผ่านกล้อง 2-4 มุมมอง
- **Then**:
  1. สคริปต์บนหน้าเว็บรันโมเดล Vision สกัด Feature Vector จากรูปภาพ
  2. ส่งรูปภาพพร้อม Vector Array ขึ้นบันทึกที่ `POST /api/v1/products/:id/images`
  3. ข้อมูลรูปภาพและเวกเตอร์ใหม่พร้อมสำหรับการซิงค์ไปยังเครื่องแคชเชียร์

# ICE POS v2 - System Specification & Cashier Design Document

**วันที่:** 2 พฤศจิกายน 2026  
**สถานะ:** เอกสารข้อกำหนดฉบับสมบูรณ์ (Approved System Specification)  
**ระบบเป้าหมาย:** ICE POS Web Client v2  
**API อ้างอิง:** `http://127.0.0.1:8080/swagger/index.html` (Swagger 2.0 - ICE POS API v2)

---

## 1. วัตถุประสงค์และเหตุผล (Intent & Why)

ระบบขายหน้าร้าน (Point of Sale - POS) สำหรับธุรกิจจำหน่ายน้ำแข็งและสินค้าอุปโภคบริโภคหน้าร้าน โดยออกแบบเป็นพิเศษเพื่อรองรับ **พนักงานแคชเชียร์ที่เป็นผู้สูงอายุ** ให้สามารถใช้งานได้อย่างสะดวกรวดเร็ว ลดความผิดพลาดในการคิดเงินและทอนเงิน ไม่เกิดความเมื่อยล้าทางสายตา พร้อมทั้งรองรับการทำงานแบบออฟไลน์ (Offline-first Synchronization) ในกรณีที่เครือข่ายสัญญาณอินเทอร์เน็ตขัดข้อง

---

## 2. ขอบเขตและกฎทางธุรกิจ (Goals, Non-goals & Business Rules)

### 2.1 เป้าหมายหลัก (Goals)

1. **การออกแบบสำหรับผู้สูงอายุ (Elder-Friendly UI/UX):**
   - ปุ่มสัมผัส (Touch Targets) ขนาดใหญ่พิเศษ อย่างน้อย 48–64px
   - ขนาดตัวอักษร 18–36px คอนทราสต์สีผ่านมาตรฐาน WCAG 4.5:1
   - ไม่ใช้ตัวหนังสือสีเทาจางบนพื้นเทา ไม่ใช้ตัวอักษรขนาดเล็ก
   - รองรับ **Light Mode** และ **Dark Mode** สลับได้ทันทีจาก Header
2. **การขายไหลลื่น ไม่ติดสต็อก (Frictionless Continuous Selling):**
   - แคชเชียร์สามารถกดขายสินค้าได้อย่างต่อเนื่อง ไม่มีการปิดกั้นหรือบล็อกการขายกรณีสต็อกหมด
3. **การชำระเงินตรงตาม API (CASH & CREDIT):**
   - **เงินสด (CASH):** มีปุ่มลัดธนบัตรด่วน (เช่น พอดีเงิน, 100 ฿, 500 ฿, 1,000 ฿) และแป้นตัวเลข (Numpad) เพื่อช่วยคำนวณเงินทอนอัตโนมัติ ไม่ต้องคิดเลขในใจ
   - **เงินเชื่อ (CREDIT):** เลือกลูกค้าจากรายชื่อ (`GET /customers`) เพื่อบันทึกยอดหนี้
   - **กฎการขายออฟไลน์ (Offline Credit Policy):** ในช่วงที่เน็ตหลุด **อนุญาตให้ขายเงินเชื่อได้** โดยเลือกลูกค้าจากข้อมูลที่แคชไว้ในเครื่อง แล้วบันทึกรายการขายลงคิวออฟไลน์เพื่อส่งไปตรวจสอบและอัปเดตที่เซิร์ฟเวอร์เมื่อเน็ตกลับมา (`POST /sync/batch`)
4. **การยกเลิกบิล (Void Sale Policy):**
   - พนักงานแคชเชียร์สามารถกดยกเลิกบิลและใส่เหตุผลได้เองทันทีจากหน้าประวัติบิล ไม่จำเป็นต้องรอรหัสผู้จัดการ
5. **การพิมพ์ใบเสร็จ (Receipt Printing):**
   - พิมพ์ใบเสร็จความร้อนขนาด 80 มม. ผ่านระบบพิมพ์มาตรฐานของเบราว์เซอร์ (`window.print()`) ร่วมกับ CSS `@media print` แสดงข้อมูลครบถ้วนทั้งตอนออนไลน์และออฟไลน์

### 2.2 สิ่งที่ไม่ทำ (Non-goals)

1. **ไม่มีการชำระเงินผ่าน QR Code / PromptPay / บัตรเครดิต:** ระบบ API ออกแบบให้รองรับเฉพาะ CASH และ CREDIT เท่านั้น
2. **ไม่มีระบบตัดสต็อกหรือแจ้งเตือนสต็อกหมดที่หน้าร้าน:** แคชเชียร์เน้นการขายที่รวดเร็ว

## 4. มาตรฐาน UI/UX สำหรับผู้สูงอายุ (Elderly Design System Tokens)

_สร้างขึ้นตามแนวทาง `ui-ux-pro-max`:_

- **ชุดสี (Color Tokens):**
  - **Primary:** `#0369A1` (Ocean Blue — มั่นคง ชัดเจน สบายตา)
  - **Success / Action (ชำระเงิน):** `#16A34A` (Green — โดดเด่นในขั้นตอนการรับเงิน)
  - **Destructive (ยกเลิกบิล/ลบ):** `#DC2626` (Red — เตือนความระมัดระวัง)
  - **Light Theme:** Background: `#F8FAFC`, Surface/Card: `#FFFFFF`, Text: `#0F172A`, Border: `#CBD5E1`
  - **Dark Theme:** Background: `#0F172A`, Surface/Card: `#1E293B`, Text: `#F8FAFC`, Border: `#334155`
- **ขนาดองค์ประกอบ (Sizing & Touch Target):**
  - ปุ่มสินค้า: สูงอย่างน้อย 80–90px, ชื่อสินค้า 18–20px, ราคาสินค้า 22–26px ตัวหนา
  - แป้นตัวเลข Numpad: ขนาดปุ่ม 64x64px ตัวเลข 24px ห่างกัน 12px (gap-3) ป้องกันการกดผิด
  - ยอดรวมเงิน (Grand Total): ตัวเลขขนาด 36–42px สีเขียวเด่นชัดสะดุดตา
  - ปุ่มชำระเงินหลัก: กว้างเต็มหน้า สูง 64px ตัวหนังสือ 24px

## 5. โครงสร้างหน้าจอและโฟลว์การทำงาน (Screen Architecture & Flows)

### 5.1 หน้าจอเข้าสู่ระบบด่วน (Quick PIN Login)

- **ช่องทางหลัก:** แป้นตัวเลขขนาดใหญ่สำหรับกรอก PIN 4–6 หลัก สำหรับพนักงานแคชเชียร์ (`POST /auth/pin-login`)
- **ช่องทางสำรอง:** ลิงก์สลับไปใช้ Username & Password สำหรับผู้ดูแลระบบ (`POST /auth/login`)
- จัดเก็บ Access Token และ Refresh Token ในคุกกี้ / LocalStorage พร้อมระบบ Auto Refresh Token (`POST /auth/refresh`)

### 5.2 หน้าจอแคชเชียร์หลัก (Main POS Screen - Hybrid Layout)

- **แถบหัวหน้าจอ (Header Bar):**
  - โลโก้ ICE POS และชื่อแคชเชียร์
  - ปุ่มสลับ Dark / Light Mode
  - ป้ายสถานะเครือข่าย: 🟢 ออนไลน์ / 🟡 ออฟไลน์ (พร้อมจำนวนบิลที่รอซิงค์)
  - ปุ่ม **"📋 ประวัติบิล"** สำหรับดูบิลย้อนหลัง พิมพ์ซ้ำ หรือยกเลิกบิล
  - ปุ่ม **"📊 สรุปยอดขาย"** (Daily Summary) และปุ่มออกจากระบบ
- **ฝั่งซ้าย (60% - Product Catalog & Scanner):**
  - แถบหมวดหมู่สินค้าขนาดใหญ่ (เช่น ทั้งหมด, น้ำแข็งหลอด, น้ำแข็งก้อน, น้ำดื่ม)
  - ช่องยิงบาร์โค้ด USB/Bluetooth พร้อม Auto-focus และค้นหาด่วนด้วยชื่อ
  - ตารางการ์ดสินค้าขนาดใหญ่ แสดงชื่อและราคาชัดเจน แตะ 1 ครั้งเพิ่มลงบิลทันที
- **ฝั่งขวา (40% - Current Bill Cart):**
  - ตารางรายการสินค้าในบิล: แสดงชื่อ, ราคาต่อหน่วย, ปุ่มปรับลด `-` และเพิ่ม `+` ขนาดใหญ่ และปุ่มลบรายการ
  - กล่องแสดงยอดรวมทั้งหมด (Grand Total) ขนาด 36px สีเขียว
  - ปุ่ม **"ล้างบิล"** และปุ่มใหญ่สีเขียว **"💵 ชำระเงิน"**

### 5.3 หน้าต่างชำระเงิน (Checkout Modal)

- แสดงยอดเงินรวมที่ต้องชำระขนาดใหญ่
- ตัวเลือกวิธีชำระเงิน 2 รูปแบบ:
  1. **เงินสด (CASH):**
     - แป้นตัวเลข (Numpad) กรอกจำนวนเงินที่รับ
     - ปุ่มลัดธนบัตรด่วน: [พอดีเงิน], [100 ฿], [500 ฿], [1,000 ฿]
     - กล่องแสดง **"เงินทอน"** คำนวณอัตโนมัติ ตัวเลขสีเขียวขนาดใหญ่
  2. **เงินเชื่อ (CREDIT):**
     - กล่องค้นหาและเลือกลูกค้า (`GET /customers`)
     - แสดงวงเงินเครดิตคงเหลือ (หากออฟไลน์จะอนุญาตให้บันทึกตามนโยบายที่ได้รับอนุมัติ)
- ปุ่ม **"บันทึกการขายและพิมพ์ใบเสร็จ"** (`POST /sales`)

### 5.4 หน้าต่างประวัติบิลและยกเลิกบิล (Sales History & Void Modal)

- เปิดจากปุ่ม "📋 ประวัติบิล" บน Header
- แสดงรายการบิลล่าสุด ค้นหาตามเลขที่ใบเสร็จ หรือกรองตามวันที่
- แต่ละบิลมี 2 ปุ่มสำคัญ:
  - **"🖨️ พิมพ์ซ้ำ":** เปิดใบเสร็จขนาด 80mm เพื่อสั่งพิมพ์
  - **"❌ ยกเลิกบิล (Void)":** เปิดหน้าต่างให้เลือกหรือกรอกเหตุผล (เช่น ลูกค้าเปลี่ยนใจ, คีย์ผิด) แล้วกดยกเลิกได้ทันที (`POST /sales/{id}/void`)

### 5.5 หน้าต่างสรุปยอดประจำวัน (Daily Summary Drawer)

- ดึงข้อมูลจาก `GET /reports/sales-summary` และ `GET /reports/best-sellers`
- สรุปยอดขายรวม, จำนวนบิล, ยอดเงินสด, ยอดเงินเชื่อ, และยอดบิลที่ถูกยกเลิก

## 6. การแปลงหน่วยเงินและข้อมูล API (API Contract & Currency Conversion)

> **ข้อกำหนดสำคัญมาก:** API ของระบบ ICE POS v2 จัดเก็บและส่งค่าเงินในหน่วย **สตางค์ (Satang - Integer)** ทั้งหมด

| ฟิลด์ใน API                | หน่วย API    | การคำนวณและแสดงผลใน UI                     | ตัวอย่าง                          |
| -------------------------- | ------------ | ------------------------------------------ | --------------------------------- |
| `unit_price`, `cost_price` | สตางค์ (int) | แปลงเป็นบาท: `satang / 100`                | `5000` สตางค์ = `50.00 ฿`         |
| `tendered_amount`          | สตางค์ (int) | แปลงจากบาทที่รับ: `Math.round(baht * 100)` | รับเงิน 100 บาท ส่ง `10000`       |
| `change_amount`            | สตางค์ (int) | แปลงเป็นบาท: `change / 100`                | `5000` สตางค์ = เงินทอน `50.00 ฿` |
| `gross_total`, `net_total` | สตางค์ (int) | แปลงเป็นบาท: `total / 100`                 | แสดงผลในบิล                       |
| `payment_method`           | string       | `"CASH"` หรือ `"CREDIT"`                   | เลือกจากแท็บชำระเงิน              |

## 7. กลไกการทำงานออฟไลน์ (Offline-First Architecture)

1. **การดาวน์โหลดข้อมูลเริ่มต้น (Sync Pull):**
   - เมื่อระบบออนไลน์ จะดึงข้อมูลสินค้าและหมวดหมู่ผ่าน `GET /sync/changes` หรือ `GET /products`, `GET /categories` และรายชื่อลูกค้า `GET /customers` มาเก็บไว้ใน IndexedDB
2. **การบันทึกการขายขณะออฟไลน์:**
   - สร้าง UUID ประจำบิล (`crypto.randomUUID()`) และรหัสบิลชั่วคราว เช่น `OFFLINE-YYYYMMDD-XXXX`
   - บันทึกรายการบิลลง IndexedDB ในคิว `offline_sales`
   - พิมพ์ใบเสร็จจากข้อมูล Local State ได้ทันที
3. **การซิงค์ข้อมูลกลับขึ้นเซิร์ฟเวอร์ (Sync Push):**
   - เมื่อระบบตรวจพบว่ากลับมาออนไลน์ จะรวบรวมบิลใน `offline_sales` ส่งไปยัง `POST /sync/batch` อัตโนมัติ
   - แสดงแจ้งเตือนผลการซิงค์ให้แคชเชียร์ทราบ
